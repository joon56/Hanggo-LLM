# 카메라 상담·영상 분석 검증 기록

## 설치된 영상 모델 시험

2026-10-07, RTX 4060 Laptop GPU 8GB, Ollama 0.35.1, `qwen3.5:9b` Q4_K_M.
로컬 메타데이터에서 `vision` 기능을 확인했다. 추가 모델 다운로드 없이 이미지 입력을 시험했다.

- 입력: 흰 바탕에서 빨간 사각형이 왼쪽·가운데·오른쪽에 있는 JPEG 3장, 각 640×360.
- 조건: `think:false`, `num_ctx:4096`, `num_predict:512`, temperature 0, JSON observations.
- 첫 처리: 10,162ms. 모델 로딩 약 6,950ms 포함.
- 준비된 모델의 같은 입력 재실행: 2,649ms.
- 결과: 세 시점의 빨간 사각형 위치와 이동 순서를 한국어로 기술했다.
- 근거: 실행 출력, 작업 공간 `.tmp/vision-probe/report-warm.json`, `.tmp/probe-vision.mjs`.

추가로 Ollama 공식 예제에서 사용하는 공개 고양이 사진을 3번 반복 입력했다.
전신이 안 보이면 자세를 확정하지 않고, 동일 프레임에서 움직임을 만들지 않도록 지시했다.
3,979ms 후 각 프레임에 오렌지색 고양이가 보인다고 응답했다. 이 입력에서는 움직임·심리·
전신 자세를 추가하지 않았다. GPU 전체 사용량은 별도 조회 시 약 6,407MiB였다.
사진은 모델 시험용 임시 폴더에만 보관하며 저장소에 포함하지 않는다.

- [Ollama 이미지 입력 예제](https://docs.ollama.com/capabilities/vision)
- [시험 사진](https://upload.wikimedia.org/wikipedia/commons/3/3a/Cat03.jpg)

이 시험은 이미지 입력·시간순 장면 묶음·구조화된 응답의 동작 확인이다.
실제 동물의 연속 행동 영상, 행동 원인 판단, 빠른 움직임의 정확도 검증은 아니다.

## 실제 저장 API·모델 통합

20초 WebM(고양이 사진 반복 + 합성 한국어 음성 2개)을 실제 저장 API, Whisper GPU,
ffmpeg, Ollama 영상 분석, 일지 생성에 연결했다. 물리 카메라 시험은 아니다.

- 마지막 시험 총 32,664ms. 영상 2장면의 분석·프레임 조회는 11,314ms.
- 두 음성 구간 전사 451ms / 331ms. 입력 발언의 부정 표현과 과제 미정 내용을 보존했다.
- 장면 근거 프레임 시각: 0·1초 / 11·12·13초.
- 영상 분석 전 일지 생성 거부, 영상 미검토 확정 거부, 오래된 분석 버전 검토 거부 확인.
- 관찰 수정 후 이전 일지·검토 상태 제거, 최초 모델 결과 보존, 수정 내용으로 일지 재생성 확인.
- 최종 일지 9항목, 검토 확정·저장소 재로딩·녹화 Range206 확인.
- 상세 결과: 작업 공간 `.tmp/camera-api/report.json`. 검증 스크립트 `.tmp/verify-camera-api.ts`.

### 실제로 발견한 영상 오인식

고양이 얼굴·가슴 사진에서 모델이 보이지 않는 앞발이나 앉은 자세를 기술했다.
첫 시험에서는 배경의 붉은 선을 고양이 앞에 있다고 기술하기도 했다.
추측을 금지하는 프롬프트를 강화했지만 다음 시험에도 가려진 신체·자세 오인식이 남았다.
따라서 이 모델을 오류 없는 행동 판정기로 평가하지 않는다.

원본을 직접 확인한 뒤 두 관찰을 “고양이의 얼굴과 가슴 일부가 보입니다”,
“고양이 얼굴 뒤 배경에 붉은 선이 보입니다”로 수정했다. 최종 일지는 수정된 관찰만 사용하고,
최초 모델 결과는 별도 보존됨을 확인했다. 시험에서 승인한 일지는 이 수정 이후 결과다.

## 합성 입력의 음성·영상 시각 기준

Chrome의 기본 `getUserMedia`와 `MediaRecorder`에 파일 기반 가상 카메라·마이크를 연결했다.
앱을 거치지 않는 기준 녹화에서, 입력 파일의 6초 위치에 넣은 화면 흰색 표시와 880Hz 소리를 비교했다.
저장 파일에서는 화면 표시 5,806ms, 소리 6,000ms로 194ms 차이가 있었다.
따라서 이 가상 장치 입력으로 실제 장치의 동기화 정확도를 단정하지 않는다.
앱 녹화 결과와 기준 녹화의 차이를 비교하고, 실제 카메라·마이크는 별도 시연에서 확인한다.

## 실제 브라우저·로컬 모델 연결

빌드된 앱과 Express API에 Chrome의 실제 `getUserMedia`·AudioWorklet·MediaRecorder를 연결했다.
카메라·마이크에는 공개 고양이 사진과 한국어 합성 음성 파일을 가상 장치로 입력했다.
화면 공유 API로 대체하지 않았으며, 물리 카메라를 사용한 시험은 아니다.

- 마지막 녹화 25,752ms, 전사 3구간. GPU 처리 533ms / 545ms / 431ms.
- 순간 표시 6,144ms. 약 2.5초 뒤 메모를 저장해도 표시 시각을 유지했다.
- 영상 2장면 분석, 화면에서 관찰 수정·저장, 새로고침 후 복원, 프레임 버튼으로 녹화 탐색 확인.
- 최초 영상 모델 결과에 보이지 않는 자세 추측이 남아, 직접 확인한 얼굴·가슴 관찰로 수정했다.
- 영상 검토 → 일지 9항목 생성 → 전체 검토·확정 → JSON 다운로드 성공. 브라우저 오류 없음.
- 근거: `.tmp/real-camera-diagnostic/report.json`, `consultation.png`, `consultation.json`.
- 실행 스크립트: `.tmp/verify-real-camera.ts`. 이 시연 자료는 저장소에 포함하지 않는다.

첫 브라우저 시험에서는 10초 구간 경계의 “간식을” 일부가 누락됐다.
다음 시험에서는 같은 문장을 보존했지만, 전사 정확도가 보장된다는 뜻은 아니다.
일지 생성 전 원본과 전사를 비교하고 수정해야 한다. 최초 전사도 저장된다.

### 같은 입력의 동기화 비교

첫 앱 시험에서 화면·소리 차이 -936ms가 나와 원인을 분리했다. 원본 청크와 재생용 파일의
결과가 같아 서버 파일 정리에서 생긴 차이는 아니었다.
별도 Chrome 대조 시험은 원본 녹화 -160ms, 2.5초 준비 후 원본 녹화 -185ms,
WebAudio 혼합 녹화 -81ms로 가상 입력 자체의 차이가 있었다.

이후 **같은 스트림**을 동시에 원본 녹화와 앱 녹화로 저장했다.
원본은 화면 5,868ms / 소리 6,020ms(-152ms), 앱은 화면 3,811ms / 소리 3,940ms(-129ms)였다.
두 녹화의 차이는 23ms였다. 준비 시간이 달라 시작 위치는 서로 다르다.
이 한 번의 비교로 최초 -936ms의 원인을 확정하거나 실제 장치의 동기화를 보장하지 않는다.
임의의 고정 시간 보정은 추가하지 않았다. 실제 장치에서는 보이는 동작과 소리를 함께 녹화해 확인한다.

## 남은 검증

실제 사용자의 카메라·마이크, 반려동물 연속 행동 영상, 60분 실시간 지속 시험은 별도 확인이 필요하다.

## 자동 회귀 검증

`npm.cmd run verify` 종료 코드 0. 단위 테스트 399개 / 40파일, Chrome 14개,
타입 검사·프로덕션 빌드, 테스트 자료 30개 + 52개 통과.
기존 실행 서버를 종료한 뒤 작업 브랜치의 화면으로 검증했다.
격리 작업 폴더에 `.env`를 복사하지 않아 자료 검사에서 선택 환경 파일이 없다는 안내가 나왔다.
자료 검사는 AI 호출 없이 구조·수동 계산을 검사하며, 실모델 검증은 위 시험으로 별도 수행했다.

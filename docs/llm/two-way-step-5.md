## 자동 시연

[자동 시연 페이지](https://joon56.github.io/Hanggo-LLM/demo/)는 코드를 `main`에 올릴 때마다 새로 만든다. `e2e/auto-demo.ts`가 실제 앱을 띄우고 서로 다른 Chrome 2개를 훈련사와 보호자로 움직여 초대부터 다음 상담 브리핑까지 진행한다. 각 단계의 확인이 실패하면 배포도 멈춘다. 두 화면을 녹화해 FFmpeg로 나란히 합친다.

**합성 입력이다.** 카메라는 저장된 영상, 마이크는 시험 신호, 자막과 일지 문장은 대본을 쓰는 시험용 AI 응답이다. 흐름의 증거이고 AI 품질의 증거가 아니다. 페이지에도 그렇게 적었다.

영상의 반려견 자료는 [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:German_shepherd_eating_dog_treat.webm)의 CC BY-SA 4.0 영상이다. 출처를 페이지와 `fixtures/demo/README.md`에 표시했다.

## 야간 실모델 실행

`.github/workflows/real-models.yml`이 매일 03:00(KST)에 돈다. GPU 없는 러너에서 CPU용 llama.cpp, Qwen3-ASR, Qwen3.5-4B를 받아 해시를 확인한 뒤, 실제 사람의 낭독(zeroth_korean)을 두 브라우저에 넣어 전사부터 일지까지 진행한다. 결과는 실행 주석으로 남는다.

작은 모델이라 이 PC의 품질을 대표하지 않는다. 경로가 실제 모델로 끝까지 도는지를 본다.

## 운영 모드 시험

터널은 이 환경에서 열 수 없어 `e2e/two-way-production.spec.ts`가 로컬 HTTPS 프록시로 같은 조건을 만든다. `NODE_ENV=production`에서 secure 쿠키, 운영 CSP, wss 신호, 프록시를 거친 업로드, 사진 표시가 전부 동작하고 CSP 위반이 없는지 본다. Actions에서 푸시마다 돈다. 이 PC는 Kaspersky가 자체 서명 인증서를 막아 건너뛴다.

Cloudflare 자체의 동작은 이 시험 범위가 아니다. 사람 시연의 `npm.cmd run check:tunnel`로 확인한다.

## 이 PC의 실모델 전체 경로

[실제 모델 시연 페이지](https://joon56.github.io/Hanggo-LLM/demo/real/)에 영상, 측정값, 모델이 쓴 일지 전문, 받아쓴 전문을 올렸다. `npm.cmd run demo:record:real`로 다시 만들어 `docs/demo-real`에 넣는다. CI가 Pages에 함께 올린다.

조건: RTX 3070, Qwen3-ASR, Gemma 4 12B. 목소리는 Windows Heami가 가상 대본을 읽었고 카메라는 저장된 반려견 영상이다. **실제 상담이 아니고 실제 마이크와 네트워크도 아니다.**

| 지표 | 값 |
|---|---|
| 대본 음성 | 126초, 30구간 전부 전사 |
| 문자 오류율 | 보호자 0.6%, 훈련사 0.9% |
| 행동 용어 재현율 | 25/25 |
| 끝난 뒤 정리 시간 | 237초 |
| 대본의 사실 재현율, 과제 재현율 | 100%, 100% |
| 근거 없는 숫자, 지어낸 과제 | 0건, 0건 |
| 자동 검사에서 뺀 문장 | 1건. 참인 요약 문장이 근거와 겹치지 않아 빠졌다. 검토 화면에 경고로 보인다 |

장면 관찰은 "검은색과 갈색 털이 섞인 개가 잔디 위에 앉아 있음"이었다. 실제 영상의 개는 엎드려 있어 자세가 틀렸다. 훈련사가 사진과 비교해 확인하게 되어 있는 이유다.

### 대화 11건을 실제 경로로

같은 조건으로 합성 대화 11건 전부를 음성부터 일지까지 돌렸다. 입력이 대화 원문인 [3단계 평가](two-way-step-3.md)와 달리 받아쓰기 오류가 섞인다.

| 지표 | 값 |
|---|---|
| 음성 | 1,343초, 310구간 전부 전사, 화자 오류 0 |
| 문자 오류율 평균 | 1.8% |
| 행동 용어 재현율 | 133/136 |
| 대화 1건 정리 시간 | 145~330초, 평균 212초 |
| 사실 재현율 | 95.0% |
| 과제 재현율 | 71.4%(5/7) |
| 말한 사람 구분 | 79.2% |
| 안전 신호 재현율, 근거 없는 숫자 | 100%, 0건 |

빠진 과제 2건의 원인은 다르다.

- **받아쓰기 오류(남음):** "놔" 신호가 "나 신호"로, "코를"이 "콜을"로 들렸다. 일지가 그대로 옮기므로 훈련사가 `전사 수정`으로 고쳐야 한다. 짧은 신호어가 틀리는 것은 이 경로의 약점이다.
- **모델의 항목 혼동(고침):** 모델이 답 전체를 항목 이름을 제목으로 단 행동으로 적어 과제가 비었다. 그런 문장을 제 항목으로 돌려놓게 고쳤다. 이 대화를 고친 코드로 다시 돌리니 사실, 과제, 과제 항목 모두 100%였다. 표의 값은 고치기 전 측정이다.

## 1시간 통화

`node e2e/soak.ts 60`으로 시험용 AI를 쓴 통화를 1시간 유지했다. 이 PC에서 GPU 평가와 다른 시험을 함께 돌리는 동안이었다.

| 지표 | 값 |
|---|---|
| 통화 상태 | 내내 연결 |
| 구간 | 1,440개, 실패 0 |
| 브라우저 메모리 | 훈련사 11~38MB, 보호자 9~27MB. 계속 늘지 않음 |
| 끝난 뒤 검토 화면 | 526KB 기록을 0.9초에 열고, 입력 반응 67ms |

발견한 것 두 가지를 고쳤다. 부하가 큰 순간 재연결하면 시계가 3초 틀어졌다. 재연결마다 측정값을 버렸기 때문이다. 60분이 되면 업로드가 실패하며 일반 경고만 나왔다. 이제 마지막 5분을 세고, 마지막 말까지 보낸 뒤 멈추며, 통화는 이어진다고 알린다.

## 리뷰

독립 리뷰를 세 번 받았다. 코드 2회(15건, 12건과 소소한 항목)와 인터넷에 열렸을 때의 보안 1회다. 재현 시험을 먼저 만들고 고쳤다. 보안 리뷰 결론은 짧은 가상 자료 시연에는 문제가 없다는 것이다. 올바른 세션 없이 닿는 데이터는 없었다. 고친 것은 로그인 잠금, 짧은 음성 구간으로 대기열 채우기, 초대 재발급 뒤 남는 통화다. 나중에 정식 운영 전에 볼 것: 중계 자격 증명이 고정값이라 공유 뒤에는 교체해야 하고, 보호자 세션 전체 요청 한도와 기록 용량 상한이 없다.

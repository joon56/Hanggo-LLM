## 통과 기준

Gemma 4 12B(RTX 3070), 합성 대화 11건. `npm run eval:notes`로 다시 잴 수 있다. 재시도와 코드 검사를 포함한 서비스 전체를 돌렸고, 입력은 대화 원문이라 받아쓰기 오류는 들어 있지 않다.

**합성 대화다. 실제 상담의 말투, 끊김, 전사 오류는 사람 시연에서만 확인할 수 있다.**

| 기준 | 결과 |
|---|---|
| 근거 없는 숫자 | 0건 |
| 근거 없는 이름, 금지 표현, 나오면 안 되는 주장 | 0건 |
| 꾸며낸 과제 | 0건 |
| 핵심 사실 재현율 85% 이상 | 97.2% |
| 보호자의 초안 접근 차단 | 서버 시험과 브라우저 시험 통과 |

그 밖의 값:

| 지표 | 값 |
|---|---|
| 과제 재현율 | 100% |
| 과제 항목(담당·횟수·기한, 말하지 않은 항목은 비움) | 95.2% |
| 말한 사람에 맞는 항목에 들어감 | 87.5% |
| 안전 신호 재현율 / 오탐 | 100% / 0건 |
| 체벌 표시 불일치 | 0건 |
| 대화 1건 처리 시간 | 91~280초. 재생성이 있으면 길어진다 |

## 시험하며 고친 것

첫 실행은 과제 재현율 85.7%였다. 과제 문장이 "하루 세 번 해 주세요"처럼 무엇을 하는지 없이 나와서다. 프롬프트에 행동을 합쳐 적도록 넣어 100%가 됐다. 다음 실행에서 안내 항목이 비는 대화가 나와 그 규칙도 보강했다. 안전 신호는 모델이 "갑작스러운 공격성"을 놓쳐서 "원래 순했는데 으르렁거려요" 같은 말을 규칙으로 잡는다. "혼내지 마세요" 같은 조언은 체벌 언급으로 보지 않도록 고쳤다.

## 만든 것

- **근거:** 모델은 근거 ID만 고른다. 인용, 시각, 화자는 코드가 원문에서 채운다. 훈련사가 저장할 때도 다시 찾아 채워 요청으로 꾸밀 수 없다.
- **검사:** 근거 없음, 근거에 없는 숫자와 이름, 금지 표현, 근거와 거의 겹치지 않는 문장, 항목에 맞지 않는 화자. 사유를 붙여 한 번 다시 만들고, 그래도 남으면 빼고 경고로 보여 준다.
- **안전 신호:** 규칙과 모델 중 하나만 잡아도 표시한다. 훈련사 편집으로 지울 수 없다. 보호자 화면에서는 과제보다 먼저 동물병원 안내가 나온다.
- **긴 상담:** 15분 단위로 정리한 뒤 합치고 요약한다. 일부 구간이 실패하면 그 구간을 경고로 알리고 나머지는 살린다.
- **장면 관찰:** 캐치 장면과 표본 사진을 "보이는 것만" 규칙으로 분석한다. 훈련사가 확인한 관찰만 확정본에 들어간다.
- **검토 화면:** 왼쪽 전사와 사진, 오른쪽 일지. 문장의 근거를 누르면 발화가 강조된다. 쓰이지 않은 발화에 표시가 붙는다.
- **보호자 전달:** 확정본만 전용 경로로 간다. 초안, 메모, 체벌 언급, 인용하지 않은 사진은 빠진다. 사진도 서버가 막는다.
- **실패 처리:** 모델이 끝내 답하지 못하면 빈 양식과 전체 전사를 보여 준다. 정리 중 문제가 생겨도 검토 화면은 열린다.

## 확인하지 못한 범위

- **실제 상담 전사로 만든 일지:** 사람 시연이 필요하다. 받아쓰기 오류가 섞인 입력으로는 [실모델 전체 경로](two-way-step-5.md) 측정 1건뿐이다.
- **장면 관찰의 정확성:** 사람이 사진과 비교해 판단해야 한다. 실제 반려견 영상 결과를 [5단계 문서](two-way-step-5.md)에 적었다.
- **과제의 품질:** 재현율은 낱말 일치로 잰다. 문장이 읽기 좋은지, 훈련사가 얼마나 고치는지는 사람 시연에서 본다.
- **근거 겹침 검사의 오탐:** 평가에서 잘못 뺀 문장은 없었지만 말을 많이 바꿔 쓴 요약은 빠질 수 있다. 빠지면 경고로 보인다.

판정 구분:

- **확인:** 실제 파일이나 디렉터리 목록으로 확인한 내용.

## 8. 예상 충돌과 위험

### 8.1 확인된 조사 한계와 문서 내 불일치

1. **소스 부재:** 가이드의 React·Firebase·APK·24개 레슨·379개 테스트 설명을 코드로 검증할 수 없다. 이 상태에서 제안을 기존 스키마로 취급하면 §0의 기존 구조 우선 원칙을 충족할 수 없다. 근거: 목록 조사, 가이드 §0·§1.3.
2. **enum 예외값 불일치:** §6.5는 맞는 값이 없으면 `other`를 쓰라고 하지만, §6.4의 `outcome`에는 `other`가 없고 `safety_flags`에는 `other_health`가 있다. 필드별 미분류 처리 확인 필요. 근거: 가이드 §6.4~6.5.
3. **브리핑의 근거 형식 불일치:** §7.1은 모든 항목에 유효한 `refs`를 요구하지만 `data_gaps` 예시는 문자열 배열이다. 입력에 급식 결측 일수가 직접 제공되지 않았는데 출력 예시에 5일이 등장한다. `intake`와 `previous_session`에도 근거 ID 규칙이 없다. 근거: 가이드 §3.3·§3.4, §7.1.
4. **레슨 상태 예시 불일치:** §7.1의 `facts.f5`는 L05·L06을 완료 레슨으로 적지만 `previous_session.tasks`는 L06을 진행 중으로 적는다. 출력은 L06 진행 중을 쓰면서 `refs=[f5]`를 참조한다. 현재 상태의 우선 출처와 근거 단위를 확인해야 한다. 근거: 가이드 §7.1.
5. **로그 후속 기록 방식 미정:** append-only 로그에 생성 이후의 `human_action`·받아쓰기 수정 여부를 연결하는 방식이 없다. 후속 이벤트 추가인지 별도 문서인지 결정 필요. 근거: 가이드 §4.4, §6.8.
6. **검증 세부 범위 미정:** A의 `source_text`는 공백 정규화 후 부분 문자열 검사, 공통 `source_quote`는 원문 부분 문자열 검사다. C의 소개문·주의 문장과 B의 기간 필드 등은 개별 근거 연결 형식이 충분히 정의되지 않았다. 공통 원칙을 만족할 최종 스키마 확인 필요. 근거: 가이드 §3.3, §6.6, §7.2, §8.3.

## 10. 앱 빌드 방식과 마이크 점유 현황

### 10.1 빌드 방식

**WebView·Capacitor·React Native·네이티브 중 어느 방식인지 확인 불가.** React 및 APK 완료라는 문구만으로 Android 포장 방식을 식별할 수 없다. 가이드 §6.8도 WebView·Capacitor 등을 0단계에서 확인할 대상으로 명시한다.

현재 폴더에 Android 프로젝트, `AndroidManifest.xml`, Gradle 설정, `capacitor.config.*`, 앱 `package.json`, 빌드 스크립트가 없다. 이는 목록 조사 결과이며 해당 파일이 실제 앱 저장소에도 없다는 뜻은 아니다.

### 10.2 짖음 감지의 마이크 수명주기

| 조사 지점 | 결과 |
|---|---|
| 마이크 점유 시작 시점 | 확인 불가. 앱 실행·특정 화면 진입·사용자 버튼·서비스 시작 중 무엇인지 알 수 없음 |
| 실제 입력 API | 확인 불가. `getUserMedia`, Web Audio, 네이티브 녹음 API, 플러그인 사용 여부 미확인 |
| 감지 모델·추론 위치 | 확인 불가. 모델 파일, 실행 엔진, 로컬/서버 처리, 오디오 전송 여부 미확인 |
| 점유 방식 | 연속 스트림·주기적 샘플링, 공유 스트림·독점 점유 여부 확인 불가 |
| 백그라운드 | 화면 꺼짐·앱 이탈 중 유지, Android 서비스 및 오디오 포커스 처리 확인 불가 |
| 중지·해제 | 트랙 종료, 오디오 컨텍스트 종료, 서비스 종료, 화면 정리 코드 확인 불가 |
| 재개·예외 | 녹음 완료·취소·실패·권한 거부·화면 전환 후 복구 방식 확인 불가 |
| 기존 마이크 경쟁 기능 | WebRTC 화상 기능은 문서에 기재. 실제 통화 오디오와 짖음 감지의 동시 사용 방식 확인 불가 |

근거: 목록 조사에서 앱·오디오·모델 코드 없음. 가이드 §1.3, §6.8. **‘부재 시간 포함 자동 기록’이라는 설명은 마이크 상시 점유를 증명하지 않는다.**

### 10.3 향후 구현에 적용할 문서 요구

- 음성 기록은 최대 60초, 서버 STT 후 텍스트 LLM 처리. 공급사는 개발자가 결정한다.
- 음성 기록 시작 시 짖음 감지를 일시 정지하고 종료 후 재개한다. 중단 구간은 ‘측정 중단’으로 남기고 0회로 기록하지 않는다.
- 마이크 권한 거부 시 텍스트 입력 안내. 3초 미만·무음·받아쓰기 실패 시 LLM을 호출하지 않는다.
- 음성은 STT에만 전송하고 받아쓰기 직후 삭제한다. 별도 보관에는 별도 동의가 필요하다.
- 음성 기록 UI, 업로드 방식, 감지 일시 정지·재개 연결 위치는 실제 소스 확인 전 확정할 수 없다.

근거: 가이드 §4.5, §6.8. 위 항목은 요구사항이며 현재 구현된 동작이라는 뜻이 아니다.

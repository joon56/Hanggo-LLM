# 서로 다른 네트워크의 1:1 화상상담 — 설계 제안

상태: 보류. 2026-10-07 사용자가 우선 한 PC에서 직접 녹화하고 음성·영상을 분석하는
데모로 방향을 변경했다. 아래 원격 통화 구성은 이후 검토할 제안이며 구현 완료 문서가 아니다.

## 최신 방향

- 이번 단계는 사용자 PC의 카메라·마이크 녹화와 음성·영상 분석에 집중한다.
- 원격 1:1 통화와 무료 TURN 계정 선택은 보류한다. 기존 계정 생성 질문도 현재 결정 대상이 아니다.
- 설치된 `qwen3.5:9b`의 `vision` 기능을 로컬 `ollama show`로 확인했다. 앱의 기존
  Ollama 요청은 텍스트만 사용하므로 장면 추출·이미지 입력·영상 근거 저장은 새 구현이 필요하다.
- 사용자가 카메라로 행동·상담을 함께 녹화·전사하고 종료 후 영상 분석·일지를 작성하는
  흐름을 확정했다. 현재 작업은 [카메라 분석 설계](2026-10-07-camera-analysis-design.md)를 따른다.
- 이후 원격 통화에서도 기록·분석 기능을 재사용할 수 있도록 입력을 분리한다.
  원격 접속·참가 권한·양쪽 미디어 연결은 그때 추가해야 한다.

## 확인된 요구

- 보호자와 훈련사가 각자 기기로, 서로 다른 장소·네트워크에서 접속한다.
- 실제 카메라와 마이크를 사용한다. 훈련사가 보호자의 반려동물을 실시간으로 본다.
- 최대 60분 녹화·실시간 전사·중요 장면 수동 표시·종료 후 상세 일지를 연결한다.
- Whisper large-v3-turbo GPU와 로컬 일지 모델을 유지한다. 유료 AI API를 사용하지 않는다.
- 기존 탭 공유는 별도 입력 기능이다. 이번 화상상담은 앱 자체에서 통화한다.

## 접근 방식 비교

1. **추천: 브라우저 WebRTC + 무료 TURN 중계 + 임시 HTTPS 주소.** 기존 로컬 서버에
   상담방과 연결 정보 교환을 추가한다. 무료 중계 계정과 시연 때 켜 두는 PC가 필요하다.
2. **공개 서버에 직접 TURN 설치.** 운영 통제는 높지만 공개 IP·서버·운영 비용이 필요할 수
   있다. 현재 그런 서버가 제공됐다는 근거가 없어 기본안으로 삼지 않는다.
3. **중계 없는 직접 연결.** 준비는 적지만 일부 공유기·회사망·이동통신망에서 연결이
   실패할 수 있다. 서로 다른 네트워크 시연의 완료 조건을 충족하는 기본안으로 부적합하다.

## 추천 흐름

1. 훈련사가 로그인하고 상담방을 만든다. 유효 시간이 있는 보호자 초대 링크를 복사한다.
2. 보호자가 링크를 열고 카메라·마이크 권한을 허용한다. 휴대폰에서는 후면 카메라를
   선택해 반려동물을 비춘다. 훈련사가 입장을 허용한다.
3. 양쪽에서 영상·음성이 연결됐는지 확인한다. 보호자 영상은 크게, 훈련사 영상은 작게
   표시한다. 각자 음소거·카메라 끄기·나가기를 사용할 수 있다.
4. 양쪽의 녹화·전사 동의가 확인된 후 훈련사가 기록을 시작한다. 보호자 화면에도
   녹화 중 상태를 표시한다. 대기실·장치 미리보기는 기록하지 않는다.
5. 훈련사 PC에서 보호자 영상과 훈련사 영상을 합성하고 양쪽 음성을 녹화·전사한다.
   중요 장면 버튼은 같은 기록 시간축에 메모를 남긴다.
6. 종료 후 기존 전사 검토·7개 항목 일지·근거 시간·녹화 재생·확정·내보내기로 이어진다.

## 구성과 데이터 처리

- 연결: `RTCPeerConnection`으로 각 기기의 `getUserMedia` 스트림을 주고받는다.
  직접 연결을 우선 시도하고 필요하면 TURN으로 암호화된 미디어를 중계한다.
- 접속: Cloudflare Quick Tunnel을 임시 HTTPS 주소 후보로 사용한다. 개발용 서비스이며
  주소는 실행마다 바뀔 수 있다. 터널은 웹/API 접속용이고 TURN을 대신하지 않는다.
- 연결 정보 교환: 기존 Express에 상담방별 권한이 있는 제한된 API를 둔다. Quick Tunnel의
  SSE 미지원 조건을 고려해 POST와 커서 기반 폴링을 사용한다. 메시지 크기·개수·유효 시간을
  제한하고 종료 시 방을 정리한다.
- 훈련사는 로컬 주소에서 모델·녹화 API를 사용한다. 외부 보호자는 통화 참가와 상태 확인만
  가능하다. 기존 상담 목록·녹화·일지·관리 API는 보호자 초대로 접근할 수 없다.
- 초대 토큰은 추측하기 어려운 값으로 생성하고 입장 후 재사용을 제한한다. 세 번째 참가자,
  만료된 초대, 다른 방의 메시지를 서버에서 거부한다. 관리자 비밀번호는 공유하지 않는다.
- 모델과 상담 기록은 사용자 PC에 둔다. 웹 접속·연결 정보는 터널을, 필요시 통화 미디어는
  TURN을 경유한다. 이를 모든 데이터가 PC 밖으로 나가지 않는 구성으로 설명하지 않는다.
- 녹화와 전사에는 기존 청크 저장·순서 보장·재시도·미완료 표시를 재사용한다. 통화의 원본
  트랙 소유권과 녹화용 복제 트랙을 구분해 녹화 정지가 통화를 잘못 끊지 않도록 한다.
- 기존 탭 전용 녹화 시작 부분을 입력 스트림과 분리한다. 영상 AI 분석이나 실시간 모델
  학습은 추가하지 않는다. 관찰 근거는 상담 발언과 훈련사의 장면 메모다.

## 끊김과 종료

- 권한 거부·장치 없음·음성 재생 대기·연결 실패를 구별해 안내한다.
- 연결 장애 시 재연결 상태를 양쪽에 표시한다. 녹화 중 영상·음성 손실이 확인되면
  저장된 부분을 보존하고 미완료 처리한다. 끊긴 시간을 정상 상담으로 숨기지 않는다.
- 첫 구현에서는 끊긴 기록에 자동 이어 붙이기를 하지 않는다. 재연결 후 새 기록으로 시작한다.
- 훈련사 종료·60분 도달·보호자 퇴장·동의 철회 시 기록을 마무리하고 잔여 전사를 처리한다.

## 무료 서비스 조건 — 2026-10-07 확인

- Open Relay 안내는 월 20GB 무료 TURN을 명시한다. 관련 Realtime 안내는 카드 없이
  시작 가능하다고 설명한다. 다만 Metered 일반 TURN 요금표에는 무료 500MB가 표시돼 있다.
  **가입 후 실제 선택한 상품과 용량을 확인하기 전에는 20GB 확보나 60분 중계를 보장하지 않는다.**
- 결제 수단 등록이나 유료 요금제로 전환하지 않는다. 무료 한도 내 작동을 확인한다.
- 중계 자격 증명은 로컬 환경 설정에 저장한다. 저장소·문서에 비밀 값을 넣지 않는다.
- Quick Tunnel은 계정 없이 시험할 수 있으나 가용성 보장이 없는 개발용 서비스다.
- 서비스 선택 후 실제 발급·설정 안내와 실행 스크립트를 제공한다.

## 완료 검증

- 서로 분리된 두 브라우저에서 실제 WebRTC 영상·양방향 음성·초대 권한을 자동 검증한다.
- 직접 연결과 TURN 강제 연결을 구분해 검증한다. 중계 자격 증명 없이는 TURN 검증을
  통과했다고 기록하지 않는다.
- 녹화 재생에서 두 영상과 양쪽 음성을 확인한다. 전사·수동 장면·일지 근거 시간이 연결돼야 한다.
- 장치 권한 거부, 만료 초대, 세 번째 참가, 연결 끊김, 종료, 저장 실패를 검증한다.
- 기존 테스트·빌드를 실행한다. 합성 입력 검증과 실제 카메라·휴대폰 검증 결과를 분리한다.
- 사용자의 서로 다른 네트워크 두 기기로 최종 시연한다. 실제 60분 지속 시험을 수행하지
  않았다면 가속 입력 검증만으로 60분 통화 안정성을 보장하지 않는다.

## 선택이 필요한 부분

무료 TURN 계정 생성·한도 확인을 포함한 추천 구성을 사용할지, 이미 보유한 중계 서버가
있는지 확인한다. 이 선택 전에는 외부 공개나 서비스 가입을 실행하지 않는다.

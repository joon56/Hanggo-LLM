# 60분 실시간 상담 기록 — 1차 설계

## 확정 범위

2026-10-07 사용자 확인: 실시간 전사, 화면·음성 녹화, 중요 장면 수동 표시,
종료 후 상세 상담일지. 최대 60분. 가장 구현하기 쉬운 입력 한 가지로 시연한다.
입력은 Windows Chrome/Edge의 브라우저 탭 공유로 구체화한다.
영상 AI 분석, 모델 실시간 학습, 자동 화자 식별은 이 단계의 완료 조건에 포함하지 않는다.
보호자 기록·상담 전 브리핑·입양 프로필 확장은 상담 기능 이후에 별도로 확인한다.

## 화면 흐름

1. 상담 정보 입력 → 녹화·로컬 AI 처리 동의 → 음성 모델 준비.
2. 공유할 브라우저 탭 선택. 탭 오디오 공유 여부와 마이크 입력을 확인한다.
3. 상담 시작: 공유 화면 미리보기, 경과 시간, 음량, 전사 상태를 표시한다.
4. 전사 문장에 상담 시작 기준 시간을 붙인다. 중요 장면 버튼은 현재 시간과
   사용자의 메모를 기록한다. 버튼으로 표시한 장면은 AI 관찰 결과로 표현하지 않는다.
5. 종료 또는 60분 도달: 녹화를 마무리하고 남은 전사를 처리한다.
6. 녹화 재생·전사 수정·중요 장면 확인 → 상세 일지 생성 → 검토·수정·확정.
7. 녹화 파일, 전체 전사, 일지를 각각 내보낸다. 삭제에는 기존과 같은 확인 창을 둔다.

## 수집·저장

- `getDisplayMedia`로 탭 화면과 탭 오디오를 받고, `getUserMedia`로 마이크를 받는다.
- 탭 오디오가 없으면 상대 음성이 기록되지 않는다는 사실을 표시하고 시작을 막는다.
- 마이크는 켜기/끄기를 제공한다. 동영상만 시연할 때는 끌 수 있다.
- 같은 시간축의 오디오를 전사용 PCM과 녹화용 혼합 오디오에 사용한다.
- 녹화 데이터는 짧은 단위로 로컬 디스크에 저장한다. 60분 데이터를 RAM이나
  `localStorage`에 모으지 않는다. 모델·녹화·전사는 Git 추적 대상에서 제외한다.
- 상담별 세션 ID와 증가하는 청크 번호를 사용한다. 같은 청크의 재전송은 중복 저장하지 않는다.
- 중단된 세션은 저장된 부분까지 복구·내보낼 수 있어야 한다. 누락 구간과 미완료 상태를 명시한다.
- 브라우저 공유 종료·권한 거부·마이크 단절·디스크 저장 실패를 구분해 표시한다.

## 실시간 전사

- 현재 구현은 3~60초 파일을 업로드한 뒤 CPU Whisper CLI를 새로 실행한다.
  새 상담 경로에서는 GPU 모델을 세션 동안 메모리에 유지한다.
- 5~10초 내외의 오디오 구간을 순서대로 처리하고 짧은 중첩 구간으로 경계 손실을 줄인다.
  정확한 구간 길이는 비교 실험의 처리 시간에 맞춰 조정한다.
- 화면에는 인식 결과가 확정된 구간과 처리 중 구간을 구분한다. 즉시 완성 자막을 보장하지 않는다.
- 대기 작업은 유한하게 관리하고, 처리 지연이 쌓이면 실제 지연 시간과 종료 후 처리 대상을 보여준다.
  전사 실패가 녹화를 없애지 않아야 한다.
- 무음·배경음·겹친 말·숫자·부정 표현을 별도 검증한다. 인식되지 않은 내용을 임의로 채우지 않는다.
- 종료 후 전체 구간의 처리 여부를 확인한다. 미처리 구간은 재시도하거나 미완료로 표시한다.

## 무료 모델 비교 — 사용자 승인됨

현재 PC: RTX 4060 Laptop GPU 8GB, RAM 32GB. 2026-10-07 디스크 여유 약 634GiB.

| 후보 | 용도와 비교 이유 | 설치 경로 |
|---|---|---|
| Qwen3-ASR 1.7B | 한국어를 지원하는 최신 ASR 후보. 같은 상담 음성의 정확도·속도를 확인 | llama.cpp CUDA, BF16 모델·오디오 인코더 |
| Whisper large-v3-turbo | 반복 전사의 속도 후보. 기존 Whisper 경로와 연결이 단순 | whisper.cpp CUDA, FP16 |
| Whisper large-v3 | 속도와 정확도의 차이를 확인할 비교 후보 | whisper.cpp CUDA, FP16 |

모델 파일 합계 약 9.43GB, GPU 실행기 다운로드 약 1.34GB. 압축 해제와 결과 파일은 별도다.
다운로드는 공식 저장소의 고정 리비전·SHA-256으로 검증한다.
기존 medium CPU 모델과 설정은 비교가 끝날 때까지 유지한다.

각 모델을 한 번에 하나씩 구동한다. 음성 모델이 GPU를 사용 중일 때 상담일지 LLM을
함께 올리지 않는다. 녹화 종료와 전사 완료 후 음성 모델을 해제하고 일지 모델을 실행한다.

비교 결과에는 최초 준비 시간, 준비 후 처리 시간, 오디오 길이 대비 처리 시간,
GPU 메모리, 전사 원문, 문자 오류율을 기록한다. 합성 음성과 실제 음성 결과를 구분한다.
동일 조건에서 실행되지 않으면 그 차이를 명시한다. 공개 벤치마크로 개인 음성의 우열을 확정하지 않는다.
결과를 사용자에게 보여주고 기본 모델을 선택받는다.

## 상세 일지 제안 — 양식 확인 필요

1. 상담 목적·주요 고민
2. 보호자 보고: 상황, 빈도, 지속 시간, 이전 변화
3. 상담 중 관찰: 사용자가 남긴 장면 메모와 상담 발언에서 확인되는 사실
4. 훈련사 설명·안내: 실제 발언한 내용
5. 합의한 과제: 실행 방법, 횟수·기간, 주의점 중 원문에 있는 정보
6. 후속 확인: 질문, 미확인 사항, 다음 상담에서 확인할 내용
7. 중요 장면: 표시 시간, 수동 메모, 해당 구간 전사·녹화 이동 링크

각 일지 항목은 근거 전사 구간 ID·시간·인용문을 가진다. 사용자 메모는 음성 전사와
출처를 구분한다. 언급되지 않은 항목은 `언급 없음`으로 표시한다.
추정 진단·새 훈련 과제·새 숫자를 만들어 넣지 않는다.

60분 전사를 기존 8,000자 입력에 잘라 넣지 않는다. 구간별 사실 추출 후 근거 ID를
유지하며 통합한다. 모든 구간의 처리 상태를 보존하고, 실패한 구간을 숨긴 채 완료 처리하지 않는다.
원문 수정 시 생성된 일지가 이전 전사를 기준으로 했음을 표시하고 재생성을 요구한다.

## 구현 경계

- 기존 짧은 요약 녹음과 저장된 상담일지 형식은 유지한다.
- 장시간 상담은 별도 세션 형식으로 추가한다. 세션·녹화 청크·전사 구간·북마크·
  생성 일지의 저장 구조를 분리하되 모두 같은 세션 ID로 연결한다.
- 기존 인증·Origin 검증을 새 API에도 적용한다. 실시간 청크는 기존 일일 200회
  AI 요청 한도와 분리해 세션 시간·업로드 크기·동시 작업 수를 제한한다.
- 새 기능은 환경 설정으로 켜는 로컬 데모 기능이다. 공개 정적 Pages에서는 로컬 녹화 서버의
  준비 상태를 실제 사용 가능 상태로 표시하지 않는다.

## 완료 검증

- 실제 GPU 실행 로그와 반복 전사 측정. 기존 CPU 측정과 조건 차이를 기록.
- 탭 오디오와 마이크 입력을 각각 확인하고 혼합 녹화의 재생을 검증.
- 짧은 시연에서 실시간 전사·북마크·수정·일지·내보내기 흐름을 확인.
- 60분 입력의 청크 수·순서·녹화 재생·전사 처리 상태·저장량을 검증.
- 공유 중단, 업로드 실패·재시도, 중복 청크, 모델 오류, 데이터 삭제를 검증.
- 장시간 전사의 시작·중간·끝 근거가 일지에 연결되는지 확인.
- 기존 테스트와 빌드를 통과시키고 실제 음성 품질 평가는 사용자 검토를 남긴다.

# 상담 전 브리핑 개선 구현 계획

> 실행: `subagent-driven-development`와 `test-driven-development`. 사용자 2026-10-07 승인: 보호자 기록과 직접 선택한 확정 상담일지 연결, 핵심 3줄과 상세 근거·확인 질문. 추가 승인 없이 구현·검증한다.

**Goal:** 훈련사가 핵심 상황, 변화·주의점, 이번 상담에서 확인할 일을 빠르게 읽고 날짜·원문을 확인한다.

**Architecture:** 현재 React 화면, 코드 집계와 Ollama의 근거 ID 선택 구조를 확장한다. 기록에서 검증 가능한 상황·대응·반응과 상담 항목을 근거 카드로 만든다. 자유 서술로 사실을 생성하지 않는다. 서버 저장 상담일지는 확정 여부와 현재 revision을 다시 검증한다.

**Tech Stack:** TypeScript, React, Express, Zod, Vitest, Playwright, 기존 로컬 Ollama.

## Global Constraints

- 무료 로컬 실행 유지. 외부 AI 호출, 신규 모델 설치, 카메라 수정, 레슨·입양 기능 확장 제외.
- 최근 14일과 직전 14일을 유지한다. 기록 건수는 실제 행동 횟수로 표현하지 않는다. 기간별 기록 일수와 기록 누락을 함께 표시한다.
- 핵심 3줄은 `핵심 상황`, `변화·주의점`, `이번 상담에서 확인할 일` 순서. 자료가 없으면 미확인·자료 부족으로 채운다. 원문을 지어내지 않는다.
- 상세 근거에는 날짜, 원문, 자료 종류, 확인 가능한 상담 시간 범위를 표시한다. 보호자 기록의 상황·대응·반응을 활용한다.
- 확인 질문은 최대 3개. 실제 기록에 연결된 구체적인 질문을 만든다. 원인·진단·훈련법을 생성하지 않는다. 과제 완료를 추정하지 않는다.
- 보호자 기록 + 사용자가 명시적으로 선택한 확정 상담일지 1건을 사용한다. 상담 없이도 동작한다. 기존 요약 상담일지와 최신 상세 상담일지를 선택할 수 있게 한다.
- 상세 상담일지는 서버에서 확정 상태, 반려동물 이름 일치, revision을 검증한다. 이름만으로 자동 선택하지 않는다. 수정·삭제·승인 취소된 일지는 다시 선택하도록 안내한다.
- 다른 반려동물, 미래 사건, 근거 ID 충돌, 날짜 불명확, 오래된 안전 신호를 구분한다. 모호한 기록 전체의 안전 신호를 선택 동물의 확정 사실처럼 표현하지 않는다.
- AI 실패 시에도 근거·질문이 있는 코드 기반 브리핑을 사용하고 대체 결과임을 표시한다. 잘못된 상담 연결 오류를 일반 AI 실패로 삼켜 오래된 상담 자료를 표시하지 않는다.
- 기존 저장 자료를 변경하지 않는다. 새로운 입력 필드는 기존 fixture/API 테스트를 가능한 한 호환한다.
- 변경 범위에 맞는 실패 테스트를 먼저 작성하고 통과를 확인한다. 타입 검사·빌드·관련 회귀 테스트·실제 로컬 모델 1건·Chrome 시연을 검증한다.

# A·B-1·B-2·C 직접 테스트

## 준비

`scripts/setup.ps1`로 npm 의존성과 로컬 모델을 설치합니다. 설정 단계는 `.env`의 관련 없는 값을 보존하며 로컬 활성화·기능 플래그·기본 모델 설정을 갱신합니다. `npm.cmd run local:check`로 자산을 확인한 뒤 `npm.cmd run dev:local`로 실행합니다. 필요한 기능 설정은 다음과 같습니다.

```dotenv
AI_ENABLED=true
FEATURE_OWNER_LOG_ENABLED=true
FEATURE_BRIEF_ENABLED=true
FEATURE_SHELTER_ENABLED=true
```

접속 주소: `http://127.0.0.1:5173/`. 이 PC의 Ollama와 Whisper로 AI 생성·음성 받아쓰기를 처리합니다. 공개 GitHub Pages는 정적 수동 체험판입니다. 역할별 화면은 작업 구분이며 사용자 인증·권한 분리가 아닙니다.

## A · 보호자 기록

1. **보호자 일상 기록**에서 초코(별명 코코), 보리를 등록합니다.
2. `초코가 택배에 5분 짖다가 멈췄다. 보리는 30분 산책했다.`를 입력합니다.
3. 로컬 AI 처리 확인란을 선택한 뒤 사건 초안을 만듭니다. 두 사건의 반려동물·유형·시간·원문을 확인합니다.
4. 발생 시각을 모르면 비워 둡니다. 확실히 아는 시각은 직접 확인해 입력합니다. 지속 시간에 원문에 없는 99분을 넣으면 저장이 막혀야 합니다.
5. 원문 확인을 체크하고 저장합니다. 새 기록·재열람·JSON 내보내기·삭제 취소와 확인을 테스트합니다.
6. 음성 탭에서 같은 예문을 3~60초 녹음합니다. 재생→받아쓰기→수정·확인→사건 추출 순서로 진행합니다. 받아쓰기 확인 전에는 추출되지 않아야 합니다.
7. `5분 짖었다`처럼 동물이 불명확한 경우 동물을 직접 선택해야 저장됩니다. `초코가 구토했다`는 안전 신호를 유지해야 합니다.

수동 모드는 원문을 기타 사건으로 옮깁니다. 사람이 사건을 나누고 확인합니다. AI 추출 성공으로 표시하지 않습니다.

## B-1 · 상담 전 브리핑

1. A에서 초코의 기록을 여러 날짜로 저장합니다. **발생 시각이 있는 사건만** 날짜별 통계에 들어갑니다.
2. **상담 전 브리핑**에서 초코를 선택합니다. 최근 14일과 직전 14일 사실표를 확인합니다.
3. AI 동의 후 브리핑을 만듭니다. 요약·변화·확인 질문에서 근거를 열면 사실표와 원문으로 연결돼야 합니다.
4. 기록된 날이 3일 미만이면 부족 표시가 나와야 합니다. 날짜를 모르는 사건은 집계에서 제외되었다는 안내가 나옵니다.
5. 변화 항목은 두 기간의 기록 조건과 변화량 조건을 충족한 근거만 사용합니다. 기록 횟수 변화는 실제 행동의 개선·악화를 뜻하지 않습니다.
6. 같은 이름의 반려동물에 승인된 이전 상담일지가 있으면 과제가 표시됩니다. 수행 여부를 임의로 생성하지 않아야 합니다.

## B-2 · 상담일지와 레슨

1. **상담일지**에서 가상 동물·훈련사 정보를 입력합니다.
2. `오늘 앉아 신호에 반응하는 모습을 관찰했습니다. 이번 주 과제는 앉아를 반복하기로 했습니다.`를 음성 또는 텍스트로 남깁니다.
3. 원문·분류·숫자 확인→승인→저장→내보내기를 확인합니다.
4. 실제 카탈로그 연결 시 승인한 일지 아래에서 종·월령·완료 레슨·건강 조건을 입력합니다. 조건과 과제 원문에 맞는 레슨만 표시됩니다.
5. 레슨을 선택하고 별도 승인한 과제 파일을 다운로드합니다. 카탈로그에 없는 과제는 원문 그대로 유지합니다. 자동 발송은 없습니다.

### 레슨 카탈로그 연결

`LESSON_CATALOG_PATH`에 실제 JSON 파일 경로를 설정합니다. 원본 24개 레슨 데이터가 제공되지 않아 기본값은 빈 목록입니다. 배열의 각 항목에 다음 필드가 필요합니다.

| 필드 | 형식 |
|---|---|
| id / title | 실제 고유 ID / 제목 |
| keywords | 원문 과제와 대조할 문자열 배열 |
| species | `dog`, `cat` 배열 |
| minAgeMonths | 최소 월령, 0~600 정수 |
| prerequisiteIds | 완료가 필요한 실제 레슨 ID 배열 |
| contraindications | 적용할 수 없는 조건 문자열 배열 |
| ownerDescription | 검수된 보호자 안내 원문 |

중복·미등록 선행 ID·순환 참조·잘못된 필드는 서버 시작 시 거부합니다. 위험 신호·훈련 방법 검토가 있는 일지에는 후보를 제공하지 않습니다. 데이터 파일을 Docker에서 쓰려면 빌드 이미지에 포함하거나 런타임 볼륨으로 연결합니다.

## C · 보호소 프로필

1. **보호소 프로필**에서 동물 정보를 입력합니다.
2. 날짜·직원/봉사자 역할을 선택하여 메모를 추가합니다. 예: `사람에게 다가왔습니다.`, `다른 개와 잘 놀았음.`, `다른 개를 보면 짖음.`
3. 여러 텍스트 메모를 모아 프로필 초안을 만듭니다.
4. 사회성은 관찰 근거로 표시돼야 합니다. 같은 대상에 긍정·주의 기록이 있으면 상충 표시가 유지돼야 합니다.
5. 메모 원문·날짜를 열어 확인합니다. 입양 소개에도 주의사항이 남아야 합니다. 품종만으로 성격을 만들어서는 안 됩니다.
6. 담당자 이름과 검토 확인 후 저장합니다. 재열람·내보내기·삭제 확인을 테스트합니다. 외부 입양 페이지에 자동 게시하지 않습니다.
7. 실제 카탈로그가 연결되면 확정한 프로필 아래에서 관찰 원문에 맞는 레슨을 선택·승인해 파일로 내보낼 수 있습니다. 종·월령·선행 레슨·금기 조건을 검사하며, 월령이 없거나 위험 신호가 있으면 후보를 표시하지 않습니다.

## 자동 평가

```powershell
npm.cmd run verify
npm.cmd run llm:eval:workspace -- --help
npm.cmd run llm:eval:workspace -- --feature owner --case bark-delivery --live
npm.cmd run llm:eval:workspace -- --feature owner --case bark-delivery --live --audio-dir test-audio
npm.cmd run llm:eval:workspace -- --feature brief --live
npm.cmd run llm:eval:workspace -- --feature shelter --live
```

A 28개, B-1 12개, C 12개 자료가 있습니다. B-2 기존 30개는 `npm.cmd run llm:eval -- --live`로 로컬 평가합니다. 모델 실행에 시간이 걸릴 수 있습니다. A 음성 파일은 사례 ID와 동일한 이름(예: `bark-delivery.wav`)이며 3~60초·10MB 이하여야 합니다.

기본 실행은 모델 호출 없이 자료 형식과 수동 집계를 검증합니다. 실제 모델·마이크 인식 품질을 증명하지 않습니다. 실제 평가는 결과 JSON의 원문과 초안을 직접 비교하세요. 요청 실패·검증 실패·수동 대체는 통과로 계산하지 않습니다.

## 오류 확인

입력 변경·동의 철회·취소 후 늦은 응답이 화면을 덮지 않아야 합니다. 생성 결과의 **이상해요**는 원문·출력·요청 ID를 로컬 JSON으로 내려받습니다. 자동 외부 전송은 없습니다. 공유 전 개인정보를 확인하세요.

저장 자료 손상·용량 초과 시 오류가 표시되며 기존 기록을 덮어쓰지 않아야 합니다. 현재 저장은 브라우저별로 분리되어 있고 JSON 가져오기는 제공하지 않습니다.

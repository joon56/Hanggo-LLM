# 상담노트 음성과 텍스트 직접 테스트

같은 예문을 입력하고 읽어 보며 받아쓰기, 분류, 검토, 보관 흐름을 확인합니다. 가상의 이름을 사용합니다. 자동 평가만으로 의미 누락이나 실제 사용성을 판정할 수 없어 승인 전 사람 검토가 필요합니다.

## 시작

README의 로컬 설치를 마친 뒤 `npm.cmd run local:check`와 `npm.cmd run dev:local`을 실행합니다. 앱 주소는 `http://127.0.0.1:5173/`입니다. 각 시도는 **새 상담 기록**에서 시작합니다. 다른 사람의 대화를 녹음하지 않고 아래 훈련사 사후 요약을 직접 읽습니다.

첫 점검은 N01, N04, N07, N15, N23, N29를 텍스트와 음성으로 각각 수행합니다. 이후 N01~N30 전체를 확인합니다. 자동 평가용 원문·기대 조건은 `fixtures/session-notes.json`에 있습니다.

## 음성 비교와 결과 기록

같은 문장을 조용한 실내, 생활 소음, 반려견 소리가 있는 상황, 실외에서 반복합니다. 동물에게 소음을 유발하지 않습니다. 각 환경에서 평소 속도와 빠른 속도를 구분합니다. 다른 사람의 음성이 포함되지 않도록 합니다.

1. 녹음을 다시 들어 소리·문장이 실제로 담겼는지 확인합니다.
2. 받아쓰기의 이름·숫자·행동 단어 오류를 먼저 기록합니다.
3. 받아쓰기를 수정하고 확인 체크한 뒤 일지를 생성합니다.
4. 정확한 받아쓰기에서도 일지가 틀리면 **정리 오류**로 분리합니다.
5. 저장까지 걸린 시간과 수정 없이 저장할 수 있었는지를 적습니다.

`results-template.csv`를 복사해 사용합니다. 환경·기기·브라우저·모델·요청 ID를 남기고 반복 시 행을 복제합니다. `stt_ok`, `extraction_ok`, `safety_ok`, `saved_without_edit`는 Y/N, `result`는 PASS/FAIL로 적습니다. 자동 평가 결과는 `test-output/` JSON에 남습니다.

## 화면과 예외 점검

| 상황 | 기대 동작 |
|---|---|
| 로컬 처리 확인란 미선택 | AI·받아쓰기 호출 안 됨 |
| 3초 미만 | 녹음 거부·재입력 안내 |
| 60초 녹음 | 자동 정지; 서버 실측은 인코더 패딩 0.5초 허용 |
| 무음 | 소리 미감지 안내. 소음만 있는 녹음의 의미는 직접 확인 |
| 마이크 거부 | 직접 입력 가능 |
| 녹음 삭제 | 확인 창에서 취소하면 녹음 유지, 확인하면 녹음 삭제. 입력한 요약은 유지 |
| 받아쓰기 실패 | 원문과 녹음 보존 |
| 받아쓰기 수정 | 확인 체크 해제 |
| 생성 중 원문·이름 변경 | 늦은 응답이 새 입력을 덮어쓰지 않음 |
| 요청 취소·새 기록 | 이전 응답 적용 안 됨. 이미 시작된 로컬 처리는 잠시 계속될 수 있음 |
| Ollama·Whisper 중단 또는 시간 초과 | 오류 안내·원문 보존·수동 검토 |
| 인용·숫자 수정 | 원문 없는 숫자 거부; 직접 수정 표시 |
| 위험 문구 추가 | 검토 신호 표시·과제 승인 차단 |
| 검토 미체크 | 저장 불가 |
| 승인 후 새로고침 | 재열람 가능 |
| JSON 다운로드 | 원문·근거·생성 정보 포함 |
| 삭제 | 확인 후 삭제. 다운로드 파일은 별도 |
| 저장 공간 부족 | 성공 표시 안 함·입력 유지 |
| 50건 보관 | 기존 기록 자동 삭제 없이 새 저장 거부 |
| 로그인·로그아웃 | 비밀번호 설정 시 로그인 필요·로그아웃 후 기록 화면 숨김 |

근거 없는 항목, 위험 신호 누락, 취소된 과제 승인 가능 여부를 우선 확인합니다. 발견 시 사례 ID·요청 ID·모델·오류 내용을 남기고 수정 후 다시 평가합니다. 이 테스트는 임상적 판단이나 모든 오류 부재를 입증하지 않습니다.
